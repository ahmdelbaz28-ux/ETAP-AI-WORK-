    IEC 61850 / IEC 60870-5-104 Substation Automation & SCADA Safety Charter & PE Risk Acceptance Policy

    Document ID: SAFETY-SCADA-001
    Classification: CRITICAL RISK / INDUSTRIAL SUBSTATION AUTOMATION & SWITCHGEAR SUPERVISORY CONTROL
    Standards Compliance: IEC 61850-7-2 Clause 13 (ACSI Controls), IEC 61850-7-4, IEC 60870-5-104, IEEE C37.1, NERC CIP-005, NERC CIP-007
    Date: 2026-10-12
    Authority: Platform Safety Board / Licensed Professional Engineering (PE) Committee

    1. Executive Safety Summary

    The scada capability (StudyType.SCADA / protocol bridge, handled by agents.scada_agent.SCADAAgent and scada_protocols) integrates substation automation protocols (Modbus TCP, OPC UA, IEC 60870-5-104, IEC 61850) with core network models for real-time telemetry ingestion, state estimation, and supervisory control monitoring.

    Because erroneous, unverified, or un-interlocked supervisory control commands to high-voltage and medium-voltage switchgear can result in catastrophic equipment vaporization, fatal arc-blast incidents, equipment damage, or regional grid collapse: 1. Mandatory Select-Before-Operate (SBO) Discipline: All supervisory switching operations must adhere to a strict two-stage Select-Before-Operate (Arm-and-Fire) discipline. Direct-Execute commands on primary breakers and disconnectors are permanently prohibited. 2. Deterministic Interlock Enforcement: Hard physical and logical interlocks (breaker-disconnector interlocking, sync-check 25, ground-switch interlocking) must be verified prior to arming any control point. 3. Dual-Control Maker-Checker Governance: Critical control actions and telemetry point-mapping mutations require dual-control sign-off (api/approvals.py). Self-approval is blocked (MAKER_CHECKER_VIOLATION HTTP 403). 4. Fail-Closed Governance: The feature flag scada in api/feature_flags.py is configured with enabled=False, status="pilot", rollout_percentage=0 (PRODUCTION-certified, NOT YET ROLLED OUT). No automated control actuation or field command dispatch is admitted into live industrial networks without formal substation commissioning sign-off. 5. Zero-Guessing Constraint: Omission of host/port endpoints, protocol schemas, register mappings, or logical node definitions halts execution immediately (INSUFFICIENT_ENGINEERING_INPUT). Unreachable endpoints terminate with REAL_INTEGRATION_UNAVAILABLE. Parameter fabrication is strictly forbidden.

    3. Mandatory Operational Envelopes & Engineering Disciplines

    All SCADA operations must comply strictly with the following certified rules:

    1. Select-Before-Operate (SBO) Discipline (IEC 61850-7-2 Clause 13.5):
    2. Stage 1 (Select / Arm): Client issues SelectWithValue (SBOw). Server verifies interlocks, reserves point exclusivity, and starts countdown timer ($T_{sbo} = 3000\text{ ms}$).
    3. Stage 2 (Operate / Fire): Client issues Operate with matching control token within $T_{sbo}$.
    4. Timeout Cancellation: If Operate is not received within $3000\text{ ms}$, the armed state is unconditionally dropped and logged as SBO_TIMEOUT_ABORT.
    5. Direct-Operate Ban: Direct-operate (Operate without prior Select) is hard-blocked for all high-voltage and medium-voltage switching objects.
    6. Substation Electrical Interlocks:
    7. Isolator / Disconnector Interlock: A disconnector (CSWI / XSWI) can NOT operate unless all adjacent circuit breakers (XCBR) are verified open (Pos == OPEN).
    8. Grounding Switch Interlock: A ground switch can NOT close unless the adjacent line isolator is open and bus voltage is verified zero (PhV < 0.05\text{ pu}).
    9. Synchronism Check (ANSI 25): Breakers interconnecting two active systems must verify synchronism window: $$\Delta V \le 5.0\%, \quad \Delta f \le 0.10\text{ Hz}, \quad \Delta \theta \le 10.0^\circ$$
    10. Telemetry Quality and Provenance Discipline:
    11. Every telemetry sample carries explicit protocol source metadata (modbus, opcua, iec104, iec61850).
    12. Telemetry quality attributes adhere to standard three-state categorization:
      • GOOD: Verified live data within nominal physical bounds.
      • UNCERTAIN: Value within bounds but stale ($> 3.0\text{ s}$) or uncalibrated.
      • BAD: Value out of physical range, sensor failure, or communication loss.
    13. Simulation mode is strictly tagged (simulated: True). Live mode is strictly verified (live_connection: True, simulated: False). Simulated telemetry must never be presented as authoritative field data.

    4. Licensed Professional Engineer (PE) Review & Stamping Requirement

    Prior to deploying SCADA supervisory control profiles, telemetry point mappings, or substation automation logic: 1. Dual-Control Maker-Checker: - All SCADA configuration changes, point map updates, and automated control rules require independent review by a qualified electrical engineer (api/approvals.py). Self-approval is blocked (MAKER_CHECKER_VIOLATION HTTP 403). 2. PE Digital Signature & Site Verification: - Complete substation automation schemes, IED point lists, and single-line diagram telemetry integrations must be signed and stamped by a licensed Professional Engineer.

    6. Control-Path Lock & Dual-Control Dispatch Statement

    In accordance with Platform Safety Governance and Owner Directive: 1. Telemetry Read Paths Beta-Opening: Read and telemetry monitoring paths for locally proven protocols (Modbus TCP and OPC UA) are available at 100% Beta for engineering telemetry ingestion and state verification via explicit protocol adapter bindings. 2. Supervisory Control-Path Lock: All switchgear actuation, breaker control, setpoint adjustment, and supervisory control commands remain permanently gated behind strict Select-Before-Operate (SBO) verification and Maker-Checker dual control: - SBO Dispatch Bridge: Handled by SCADAControlExecutor in scada/control_executor.py (_dispatch_iec61850_sbo, _dispatch_modbus, _dispatch_opc_ua, _dispatch_iec104), requiring two-stage arm-and-fire discipline with verified physical readback (_verify_readback). - Dual-Control Approval Policy: Mandatory Maker-Checker dual authorization (api/approvals.py) is enforced on all control actions. Self-approval is blocked with MAKER_CHECKER_VIOLATION (HTTP 403), except when operating in owner-authorized Single-Operator Mode with validated self-confirmation. - Direct-Operate Lock: Automated actuation without human engineer check and verified interlocks is prohibited under all operational conditions.

    7. Single-Operator Mode (Owner-Authorized 12-10-2026)

    Authorization Authority: Platform Owner Order (Field Work Operational Speed Directive)
    Effective Date: 2026-10-12

    This is a deliberate, owner-accepted risk downgrade from dual-control to single-operator-with-validation — record that sentence verbatim in the safety charter.

    Operational Envelopes & Governance Rules for Single-Operator Mode:

    1. Validated Self-Confirmation Lane:
    2. The dual-human (maker-checker / second-colleague) gate on SCADA and CUA supervisory CONTROL actions is replaced with Validated Self-Confirmation: the system autonomously runs pre-flight safety validations (interlocks, operational envelopes, target parameters), presents a structured confirmation dialog showing validation results and program suggestions to the operator, and the SAME operator confirms and executes.
    3. Replay protection is enforced via content-bound confirmation digest (binds decision to exact action args, confirm_token == action.args_hash).
    4. If the operator departs from standard program suggestions, an explicit override reason is captured and logged.
    5. Personnel Qualifications:
    6. The single operator MUST be a licensed engineer or authorized field specialist holding credentials verified by RBAC (engineer or admin). Non-licensed personnel or unauthenticated users remain hard-blocked.
    7. Destructive Life-Safety Actions Hard-Refusal:
    8. High-consequence life-safety destructive actions (direct breaker trip under bolted fault, bus grounding without de-energization verification, bulk shedding) still require explicit authorization and are NEVER silently or automatically executed.
    9. Emergency Stop, Kill-Switch, and Fail-Safe Governance:
    10. Emergency kill-switch mechanisms (api/agents.py, agents/cua_base_executor.py), FAILSAFE abort loops, 60-second execution timeouts, and append-only tamper-evident SHA-256 audit logging remain 100% active, non-bypassable, and unchanged.

    [!NOTE] Feature Flag Storage Precedence: Stored .feature-flags.json on disk takes strict precedence over code defaults in api/feature_flags.py (_load_flags merge in api/feature_flags.py:288-292). Any newly configured rollout percentage or status in code becomes active in deployment only upon deployment with a new/synchronized stored flags file.
