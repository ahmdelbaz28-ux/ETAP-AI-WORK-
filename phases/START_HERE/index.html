    START HERE — كيف توجّه الوكيل المنفذ (دليل المالك)

    الدورة (تُكرَّر 9 مرات — مرة لكل مرحلة S0…S8)

    أنت ───────────► تنسخ «رسالة التسليم» للمرحلة الحالية وترسلها للوكيل المنفذ
الوكيل المنفذ ──► ينفذ المرحلة ويكتب تقريره بنموذج docs/status/REPORT_TEMPLATE.md
أنت ───────────► تلصق تقريره كاملًا في محادثتي (المستشار)
المستشار ──────► يراجع الأدلة ويرد بـ: «تصريح ببدء المرحلة التالية» أو «تصحيح/إيقاف + السبب»
(ثم تعود للخطوة الأولى بالمرحلة التالية)

    قواعد سريعة: - مرحلة واحدة فقط في كل رسالة/جلسة — لا ترسل مرحلتين معًا (منعًا لفقدان سياق الوكيل). - لا تصرّح للمنفذ بالمرحلة التالية قبل ردّي. - إن شككت أن وكيلًا آخر يعمل على المستودع، أبلغني فورًا قبل أي شيء. - قرارات المالك المعلّقة (D1–D6) في docs/status/STATUS_BOARD.md — مطلوبة تدريجيًا (D1 الآن، D2 عند S5، D4 عند S3، D6 عند S6).

    ✅ رسالة التسليم (S0) — انسخها والصقها الآن للوكيل المنفذ كما هي

    [S0 — جولة إغلاق خطة الصدق الهندسي | أنت وكيل التنفيذ الوحيد المفوض]

قوانينك الثابتة:
R1 لا ادعاء بلا أمر نُفِّذ ونتيجته الحرفية أمامك. R2 ممنوع تعديل أي ملف أثناء تشغيل الاختبارات (تجميد).
R3 ممنوع أي بيانات مختلقة أو fallback وهمي. R4 ممنوع أي مسار يتجاوز tool_policy/الموافقات.
R5 ممنوع الدفع والبوابات حمراء. R6 الدمج النهائي نظيف. R7 لا تلمس أي ملف خارج القائمة المصرَّح بها، وأي خروج يُبلَّغ مسبقًا.

الحالة المؤكدة (لا تعِد اكتشافها): HEAD == origin/main == c7cf56e6c والشجرة نظيفة · ruff = 0 · claims_audit = 16/16 · اختبارات ST = 7 passed.
نواقص مؤكدة: .venv-fix بلا pytest-xdist وبلا pytest-timeout ⇒ أي أمر -n 8 --timeout=90 يفشل الآن، وrequirements-dev.txt لا يتضمن xdist.

مهمتك (S0 — تثبيت وقياس فقط، بلا أي تعديل كود):
1) أعلن التجميد: لا كاتب ثانٍ على المستودع حتى S8 (سجّله في docs/status/STATUS_BOARD.md).
2) قرار البيئة (اختر مسارًا واحدًا وأثبته بالمخرجات):
   (أ) pip install pytest-xdist pytest-timeout في .venv-fix + أضف pytest-xdist>=3.6 إلى requirements-dev.txt
   (ب) إعلان إسقاط -n 8 و --timeout=90 من كل أوامر البوابة في هذه الجولة مع ذكر السبب.
3) أنشئ logs/baseline_2026-09-21.txt (مستثنى من git) يحوي المخرجات الحرفية لهذه الأوامر:
   git rev-parse HEAD ; git status --porcelain ; ruff check . --config ruff.toml ;
   python scripts/claims_audit.py --strict ; pytest tests/ --ignore=tests/load --ignore=tests/stress --ignore=tests/chaos -q --tb=no
   (ملاحظة Windows: التقط stderr في ملف مؤقت 1> %TEMP%\out.txt 2>&1 لتفادي فقدان مخرجات ruff.)
4) شغّل كل ملف منفردًا وسجّل زمنه: tests/test_solver_parameter_cleanup.py ثم tests/test_design_agent_scaffold.py ثم tests/test_iec60909_published_cases.py.
5) أثبت التجميد: git rev-parse HEAD قبل وبعد كل قياس = نفس القيمة.
6) اكتب تقريرك بنموذج docs/status/REPORT_TEMPLATE.md، وحدّث STATUS_BOARD (صف S0).

ملاحظة: الملفات implementation_plan.md و docs/status/* و docs/phases/* أنشأها المستشار وغير مُلتزمة في git — لا تحذفها ولا تعدّها «شجرة متسخة». أي ملف آخر غير ملتزم = توقف وأبلغ.

بوابة القبول: ملف خط الأساس موجود بأرقام حرفية · قرار البيئة منفَّذ ومُثبت · نتائج الاختبارات الثلاثة وزمن كل واحد · HEAD ثابت.
توقف عند التقرير وانتظر تصريح المستشار. لا تبدأ S1.
