    S0 — التثبيت، خط الأساس، وبيئة القياس

    الصق هذا الملف وحده للوكيل المنفذ. مرحلة واحدة = جلسة واحدة. توقف عند التقرير وانتظر التصريح.

    هويتك وقوانينك (ثابتة)

    أنت وكيل التنفيذ الوحيد المفوض الآن. R1 ممنوع ادعاء نجاح بلا أمر نُفِّذ ونتيجته الحرفية أمامك. R2 ممنوع تعديل أي ملف أثناء تشغيل الاختبارات (التجميد). R3 ممنوع أي بيانات مختلقة أو fallback وهمي. R4 ممنوع أي مسار يتجاوز tool_policy/الموافقات. R5 ممنوع الدفع والبوابات حمراء. R6 الدمج النهائي نظيف تمامًا. R7 لا تلمس ملفًا خارج القائمة المصرَّح بها، وأي خروج يُبلَّغ مسبقًا.

    حالة البداية المؤكدة — لا تعِد اكتشافها

    • HEAD == origin/main == c7cf56e6cee23451648ade93520f2b78f386ae27 والشجرة نظيفة.
    • ruff check . --config ruff.toml = 0 نتائج (أثبتها بأمرك). claims_audit --strict = 16/16.
    • tests/test_arcflash_1584_st_cases.py = 7 passed.
    • المراحل 1-1…7-4 منفذة ومدفوعة (الالتزامات: 0e09b2266, 1636e7e4b, 45a520b9d, 653a6f5aa, 7ecf3c360, 9c653d50a, 7617d30be, c7cf56e6c).
    • نقص بيئي مؤكد: .venv-fix بلا pytest-xdist وبلا pytest-timeout ⇒ أي أمر -n 8 --timeout=90 يفشل؛ وrequirements-dev.txt يتضمن pytest-timeout ولا يتضمن pytest-xdist.

    المطلوب (بهذا الترتيب)

    1. إعلان التجميد: اكتب في docs/status/STATUS_BOARD.md (القسم 2 — صف S0) أن الجولة بدأت، وأعلن أنه لا كاتب ثانٍ على المستودع حتى S8.
    2. قرار البيئة (اختر وأثبت):
    3. المسار (أ): ثبّت & .venv-fix/Scripts/python -m pip install pytest-xdist pytest-timeout ثم أضف pytest-xdist>=3.6 إلى requirements-dev.txt (بجوار pytest-timeout).
    4. المسار (ب): أعلن رسميًا إسقاط -n 8 و--timeout=90 من كل أوامر البوابة في هذه الجولة وسبب ذلك.
    5. لا تخلط بين المسارين، ووثّق المخرج الحرفي لأمر التثبيت أو سبب الإسقاط.
    6. ملف خط الأساس logs/baseline_2026-09-21.txt (علمًا أن logs/ مستثنى من git .gitignore:328 — لا تحاول دفعه؛ أثبت وجوده محليًا): 
      git rev-parse HEAD
git status --porcelain
& .venv-fix/Scripts/python -m ruff check . --config ruff.toml
& .venv-fix/Scripts/python scripts/claims_audit.py --strict
& .venv-fix/Scripts/python -m pytest tests/ --ignore=tests/load --ignore=tests/stress --ignore=tests/chaos -q <خيارات التزامن/المهلة حسب قرارك> --tb=no
      ⚠️ على Windows/PowerShell: التقط stderr في ملف مؤقت (1> %TEMP%\<name>.txt 2>&1) لتجنب فقدان مخرجات الأدوات.
    7. قياس الاختبارات المفردة (كلٌّ على حدة — تشغيلها معًا تجاوز 30 ثانية عند التحقق الاستشاري): tests/test_solver_parameter_cleanup.py ثم tests/test_design_agent_scaffold.py ثم tests/test_iec60909_published_cases.py. سجّل مخرجات كل واحد حرفيًا.
    8. دليل التجميد: أعد git rev-parse HEAD بعد كل قياس كامل وأثبت أنه لم يتغير.
    9. حدّث docs/status/STATUS_BOARD.md (صف S0 = ✅ مع الأدلة) واكتب تقريرك بنموذج docs/status/REPORT_TEMPLATE.md.

    بوابة القبول

    • قرار البيئة مُنفَّذ فعليًا ومُثبت بمخرجات حرفية (تثبيت ناجح أو إسقاط معلن).
    • ملف خط الأساس موجود بأرقام حرفية + مدة أمر pytest الكامل (سطر finished in … من pytest نفسه).
    • نتائج الاختبارات الثلاثة المفردة مسجلة.
    • git rev-parse HEAD ثابت عبر كل القياسات.

    توقف

    لا تبدأ S1. اعرض التقرير وانتظر تصريح المستشار.

    ملاحظة سياق (إلزامية)

    ملفات قيادة الجولة (implementation_plan.md وdocs/status/* وdocs/phases/*) أنشأها المستشار وغير مُلتزمة في git بعد. لا تحذفها ولا تعدّلها، ولا تعتبر وجودها «شجرة غير نظيفة» — تُدرج ضمن التزامات S7 بعنوان docs(plan): add closure plan, status board, and phase prompts. أي ملف آخر غير ملتزم = توقف وأبلغ.
