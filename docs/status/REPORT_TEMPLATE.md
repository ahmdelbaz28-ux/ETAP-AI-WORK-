# نموذج تقرير المرحلة (إلزامي — يُنسخ ويُملأ حرفيًا)

> لا يُقبل تقرير بجمل إنشائية. كل بند يحتاج **أمرًا نُفِّذ + نتيجته الحرفية**.
> إن لم تستطع إثبات بند: اكتبه في القسم (5) «غير منفذ + السبب + اقتراح الجولة القادمة».

---

## 1) هوية المرحلة

- المرحلة: `Sx — <الاسم>`
- `HEAD` قبل التنفيذ: `<sha>` — `HEAD` بعد التنفيذ: `<sha>`
- حالة الشجرة بعد: `نظيفة / غير نظيفة` (اذكر الملفات إن وُجدت)
- هل عُدِّل أي ملف خارج القائمة المصرَّح بها؟ `لا / نعم + الملف + التبرير`

## 2) جدول التعديلات

| ملف (مسار كامل) | السطر/الدالة | قبل | بعد | السبب الهندسي |
|---|---|---|---|---|
| | | | | |

## 3) الأدلة (أهم قسم)

لكل بند في البوابة: الأمر ثم المخرجات الحرفية داخل كتلة كود.

```
<الأمر>
<المخرجات الحرفية كما ظهرت — بلا تلخيص>
```

**أمثلة صياغة مرفوضة:** «الاختبارات نجحت». **الصياغة المطلوبة:** `7 passed in 18.50s`.

## 6) تحديث STATUS_BOARD

انسخ الجدول المُحدَّث (القسم 2) بعد تعديل الحالة والدليل.

## 7) طلب التصريح

> «أُغلقت Sx بالأدلة أعلاه. أطلب تصريحًا ببدء Sx+1.»
> **توقف هنا. لا تبدأ المرحلة التالية قبل رد المستشار.**

---

## قواعد ثابتة أثناء التقرير

- ممنوع تجميل أي رقم، وممنوع نقل رقم من تقرير سابق دون إعادة تشغيل الأمر.
- كل قياس مُجمَّد: `git rev-parse HEAD` قبل/بعد = نفس القيمة (عدا التزامات المرحلة المُعلنة).
- أي فشل غير متوقع: توقف وأبلغ، ولا تلتفت حوله (ممنوع `skip/xfail` لإخفاء فشل).
