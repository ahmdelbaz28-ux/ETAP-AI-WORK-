> **الصق هذا الملف وحده للوكيل المنفذ. توقف عند التقرير.**

## القواعد الحاكمة لهذه المرحلة
- **ممنوع أي دفع مباشر إلى `main`** — كل شيء يمر بفرع + PR + CI أخضر.
- **ممنوع force-push** على `main` أو أي فرع مشترك.
- **ممنوع الدمج وبوابة حمراء** أو ناقصة.
- أي تعارض: يُحل بقراءة الطرفين وقرار هندسي معلن في رسالة الالتزام — **ممنوع** `--ours/--theirs` أعمى.

## لماذا هذه المرحلة موجودة (سابقة موثقة)
التزامات الجولة الأخيرة (من `0e09b2266` إلى `c7cf56e6c`) دخلت `origin/main` مباشرة بلا PR، والفرع `feat/trust-hardening` على الريموت متأخر عند `7617d30be`. من الآن: لا تكرار لهذا.

## الملفات
لا ملفات كود جديدة — تُدفع فقط مخرجات S0–S6 (توثيق/اختبارات/إصلاحات) + `docs/status/*`.

## الخطوات
1. `git fetch origin` ثم `git switch -c fix/trust-closure origin/main`.
2. التزامات صغيرة بمدلولات واضحة (استخدم ما ينطبق فعليًا فقط — لا تختلق التزامات فارغة):
   ```
   fix(api): allow x-user-llm-* CORS headers and align BYOK documentation
   fix(iec60909): document kappa/R-X clauses and remove undocumented method claims
   docs(trust): replace unverifiable numbers with live-run evidence
   fix(chat): real emergency stop covering in-flight chat stream
   fix(dispatch): generative_design requires no system data
   ```
3. قبل كل push: `git pull --rebase origin main` ثم أعد **اختبارات المرحلة المعنية + ruff**. أي تعارض يُحل ويُوثَّق.
4. `git push -u origin fix/trust-closure`.
5. افتح PR واحدًا بعنوان: `fix: close BYOK/IEC-60909/trust-evidence gaps (S0–S6)`، وضمّن في وصفه ملخص المراحل بأرقامها الحرفية.
6. راقب كل الدورات المطلوبة حتى الاخضرار الكامل: `ci` · `quality-gates` · `ui-quality` · `secret-scan` · `api-schema` · `python-compatibility`. أي حمراء: أصلح على نفس الفرع وأعد الدفع (مع إعادة الخطوة 3).
7. قبل الدمج: `git fetch origin && git rev-parse origin/main` — إن تغيّر عن نقطة الأساس أعد الخطوات 3→6 على التحديث الجديد.
8. الدمج: **Squash** (أو عرف المستودع الموثق) ثم:
   `git ls-remote origin main` (SHA جديد) و`git status --porcelain` (نظيف).
9. لا تحذف فروعًا ليست لك، ولا تحذف تاريخًا.
